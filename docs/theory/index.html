Synthetic data & random seeds PRNG = pseudo-random number generator #

Computer-generated records that stand in for real data. A seed makes the “random” sequence repeat exactly, so everyone who runs the script gets the same dataset.

Where it is used in this project

generate_naive (V1) uses a private random.Random(seed). generate_hardened (V2) seeds the global generator but saves and restores its state with getstate()/setstate(), so calling it does not change randomness elsewhere. Both build 4,000 rows. Timestamps use datetime.now(), so the dates are not reproducible even though everything else is.

How it helps

There is no real customer data, so the project can manufacture a deliberately easy dataset (V1) and a hard one (V2) on demand, with no privacy issues, and re-create either exactly.

Shortcomings & limits

Synthetic text is only as rich as its templates: V2 has just 212 distinct sentences in 4,000 rows. Models learn the generator, not real customers, which is why V3 and the real-data validation exist.

Theory & history

A PRNG is a deterministic algorithm that produces numbers that look random. Starting it from the same seed always yields the same sequence. That is what makes an experiment reproducible.

Python offers a global generator (random.seed, random.random) and private generators (random.Random(seed)). A private one cannot be disturbed by other code.

Overfitting & memorisation #

A model that fits its training data so closely that it fails on new data. Perfect scores on a tiny, repetitive dataset are the classic symptom.

Where it is used in this project

V1 is the textbook case. Its 4,000 rows contain only 9 distinct sentences, so the baseline classifiers score macro-F1 = 1.0 and K-Means reaches silhouette = 1.0 with inertia ≈ 0. The model memorised the sentences. V2 changes the data (not the code) and the numbers become realistic: F1 ≈ 0.91, silhouette ≈ 0.33.

Data leakage & the train / validation / test split #

Leakage happens when information from the test data sneaks into training, making results look better than they are. The cure is to split first and fit everything on the training part only.

Where it is used in this project

The deep models shuffle indices with np.random.RandomState(42).permutation(n) and slice 15% test, 15% validation, 70% train. The vocabulary is built from train_texts only. V3 reuses the same seed and fractions, so V2 and V3 are scored on the identical held-out rows. The classical models use train_test_split(test_size=0.2, stratify=…).

ACID Atomicity, Consistency, Isolation, Durability #

The four guarantees that make a database transaction trustworthy.

Where it is used in this project

A – insert_feedback_batch wraps the loop in BEGIN … COMMIT and calls conn.rollback() on any exception. C – the CHECK, NOT NULL and FOREIGN KEY rules reject bad rows. D – conn.commit() writes to the file. I – provided by SQLite's own locking; the project writes no isolation code. test_rollback_on_bad_urgency_score inserts one good row and one with score 5.0 and asserts zero rows remain.

Theory & history
  • Atomicity: all of a transaction's changes happen, or none do.
  • Consistency: the data always satisfies the rules (constraints) before and after.
  • Isolation: concurrent transactions do not see each other's half-finished work.
  • Durability: once committed, data survives a crash.

History. Transaction ideas come from Jim Gray's work in the late 1970s and early 1980s; the acronym ACID was coined by Theo Härder and Andreas Reuter in 1983.

Transaction, commit & rollback #

A group of database operations treated as one unit. COMMIT makes them permanent; ROLLBACK undoes them all.

Where it is used in this project

The pattern is try: BEGIN … loop … commit() / except Exception: rollback(); raise. The bare raise re-throws the original error so callers still see it. A single transaction for all 4,000 rows is also faster than committing each row, because every commit forces a write to disk.

TF-IDF Term Frequency–Inverse Document Frequency #

Turns each text into a vector of numbers where a word scores high if it is frequent in this text but rare across all texts.

Where it is used in this project

fit_tfidf uses max_features=2000, ngram_range=(1, 2), min_df=2 (ignore words that appear in fewer than 2 texts). The matrix feeds K-Means, both baseline classifiers and the PCA plot, and the fitted vectoriser is saved with joblib so the app transforms new text identically.

src/ml_models.py · L17–20
src/ml_models.py · L104 text to matrix
pages/2_Clustering_Explorer.py · L72 reused live in the app

How it helps

Fast, needs no training data beyond the text itself, and the 2,000-feature cap keeps matrices small.

Shortcomings & limits

Bag-of-words: ignores word order and meaning (“not good” looks like “good”).

Theory & history

tfidf(t, d) = tf(t, d) × idf(t). tf counts the word in the document; idf is roughly log(N / df), so common words such as “the” get a low weight and distinctive words such as “outage” a high one. N-grams are word sequences: with ngram_range=(1,2), “app crash” is its own feature. The output is a sparse matrix (mostly zeros), stored compactly.

History. The idf idea is credited to Karen Spärck Jones (1972).

K-Means clustering (and inertia) #

An unsupervised algorithm that groups similar points into k clusters without being given any labels.

Where it is used in this project

select_k_via_silhouette fits K-Means for k = 2…12 and records inertia and silhouette; fit_kmeans fits the final model at the chosen k (k = 9 for both V1 and V2). Only the text is used: the dataset's aspect_category column is random noise, so the clusters are discovered topics.

src/ml_models.py · L23–33 the sweep
src/ml_models.py · L73–76

How it helps

Finds themes in feedback with no labelling effort.

Shortcomings & limits

You must choose k; it assumes roughly round clusters; high-dimensional sparse TF-IDF vectors make Euclidean distance a weak signal.

Theory & history

Lloyd's algorithm: place k centres, assign every point to its nearest centre, move each centre to the mean of its points, repeat until stable. Inertia is the total squared distance from points to their centres (lower means tighter clusters). n_init=10 repeats the whole thing from 10 random starts and keeps the best, because the result depends on the start.

History. Stuart Lloyd devised the algorithm in 1957 (published 1982); James MacQueen coined the name “k-means” in 1967.

Silhouette score #

Scores how well each point fits its own cluster compared with the next-nearest cluster, from −1 (wrong cluster) to +1 (perfect).

Where it is used in this project

V1 reaches silhouette = 1.0 at k = 9 (inertia ≈ 0): nine identical sentences form nine perfect clusters. V2 reaches 0.328. That contrast is shown on the Model Comparison page.

src/ml_models.py · L31
src/ml_models.py · L23–33

How it helps

A model-free way to compare different values of k.

Shortcomings & limits

Costs O(n²) distance computations, and on templated text it keeps rising with k, which is why a plain maximum fails.

Theory & history

For a point, a = mean distance to others in its cluster, b = mean distance to the nearest other cluster; s = (b − a) / max(a, b). The score is the average over all points.

History. Peter Rousseeuw, 1987.

Elbow method & Kneedle choosing k at the knee of a curve #

Pick k where adding more clusters stops paying off: the “knee” of the curve.

Where it is used in this project

select_best_k replaces argmax(silhouette). On templated text silhouette climbs almost steadily with k, so argmax would always pick the largest k tested. Two tests lock this in: the edge case (must not return the boundary k) and the clear elbow (must return 3). The chosen k is drawn as a dashed line on the Clustering Explorer page.

tests/test_ml_models.py · L50–54
tests/test_ml_models.py · L57–59
pages/2_Clustering_Explorer.py · L55 drawn on the chart

How it helps

Avoids rewarding a metric artefact; a robust, parameter-free rule.

Shortcomings & limits

Still a heuristic; for V2 the silhouette keeps rising past the chosen k = 9.

Theory & history

Kneedle normalises both axes to 0–1, draws a straight line from the first to the last point, and returns the point farthest (perpendicular distance) from that line. The distance uses a 2-D cross product divided by the line length.

Worked example (the project's own test): silhouettes {2: .10, 3: .30, 4: .32, 5: .33} → k = 3, because the jump from 2 to 3 is the knee.

History. Satopää et al., “Finding a ‘Kneedle’ in a Haystack”, 2011 (cited in the code's docstring).

Precision, recall, F1 & macro-F1 (confusion matrix) #

Metrics for classification that are more informative than accuracy when classes are unbalanced.

Where it is used in this project

The BiLSTM and DistilBERT predict a score; the code turns it into a class with 0 if p >= 0.5 else 1 (0 = critical) and calls f1_score(..., average="macro"). Test macro-F1: V1 1.00, V2 0.821, V3 0.825. Worked example (V2, all 4,000 rows, in-sample): TP=1070, FP=355, FN=275, TN=2300 gives F1(critical) ≈ 0.773 and F1(non-critical) ≈ 0.880, so macro-F1 ≈ 0.826.

How it helps

Prevents a model that ignores the minority class from looking good.

Shortcomings & limits

Depends on the 0.5 cut-off; data_insights.py sweeps 181 thresholds and finds 0.48 is barely better (F1 0.8285), in-sample.

Theory & history
  • Precision = TP / (TP + FP): of what I flagged critical, how much was right?
  • Recall = TP / (TP + FN): of all truly critical, how much did I catch?
  • F1 = 2PR / (P + R), the harmonic mean of the two.
  • Macro-F1: compute F1 for each class, then average, so a rare class counts as much as a common one.

History. The F-measure comes from C. J. van Rijsbergen's Information Retrieval (1979).

LSTM Long Short-Term Memory #

A recurrent neural network that reads a sequence one step at a time while carrying a memory, with gates deciding what to keep, forget and output.

Where it is used in this project

src/dl_lstm.py · L63

How it helps

Captures word order, which TF-IDF cannot.

Shortcomings & limits

Processes words sequentially (slow, hard to parallelise) and, here, starts with no language knowledge. Padding is not masked, so a forward pass also steps through the padding at the end of short sentences.

Theory & history

Plain recurrent nets forget early words because gradients shrink over many steps (the vanishing gradient). An LSTM adds a separate cell state and three gates (forget, input, output) so useful information can travel across a sentence.
